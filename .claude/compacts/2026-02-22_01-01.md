## Key Decisions

### 1. Hybrid Tool Isolation Architecture (Critical)

**Problem**: CC-Switch's pure tool isolation requires configuring the same provider 9 times.

**Solution**: Hybrid mode with priority system:
```
Global Providers (tool_id = 'global')
  └─ Configure once, use across all tools

Tool-specific Overrides (tool_id = 'xxx')
  └─ Override when needed

Priority: tool override > global config > default
```

**Benefits**:
- One-time configuration for shared providers
- Flexible per-tool customization
- Matches user mental model

### 2. Database Schema Design

```sql
CREATE TABLE providers (
  id TEXT NOT NULL,
  tool_id TEXT NOT NULL DEFAULT 'global',  -- Not NULL, use 'global'
  is_global INTEGER DEFAULT 0,
  is_current_global INTEGER DEFAULT 0,
  is_current_tool INTEGER DEFAULT 0,
  PRIMARY KEY (id, tool_id)
);
```

**Key Decision**: Use 'global' string instead of NULL for tool_id (SQL limitations)

### 3. Backfill Mechanism Design

Store backup in provider's meta field:
```typescript
interface ProviderBackup {
  previousProviderId: string;
  previousConfig: ProviderConfig;
  backupTimestamp: string;
}
```

Workflow:
1. Backup current config before switch
2. Execute switch
3. Optional validation
4. Success: clear backup
5. Failure: restore from backup
